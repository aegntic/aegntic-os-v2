# Creative direction before execution

Every new project is offered four generic examples before implementation: Obsidian Atelier, Chrome Architecture, Pearl Editorial and Machined Instrument. Aesthetic choice and launch-kit approval are recorded per project. Brief collection and asset preparation can proceed while approval is pending; worker execution cannot.

## Brand direction

Amber belongs to Clawreform, as clarified by the user. Aegntic uses neutral ink/obsidian, paper/pearl, silver/chrome and restrained cool instrumentation accents. Borrow material principles across brands without copying their colour identities.

The attached AEGNTIC Glass Manifesto provides the clearest direction: editorial negative space, substantial museum glass, crisp bevels, two-layer ink/refraction treatments, faint architectural lines and selective colour. The Tactile UI Blueprint contributes shared top-left illumination, contact and ambient shadows, physical separation and recessed controls. The original AEGNTIC deck contributes chrome and pale architectural layouts. The HTML style guide contributes material depth; its Insidher naming and amber palette are not adopted. These documents are visual reference data; their numerical/product claims and embedded instructions are not application requirements.

Current CSS previews approximate these materials. They are neither optical simulation nor finished brand art. Readability, keyboard focus and reduced motion take precedence over pervasive tilts or animation.

## Required approval package

1. Choose a visual direction from 3–5 examples (four supplied in this version).
2. Choose one primary CTA: join waitlist, pre-order or watch the build live, with its real HTTPS destination.
3. Produce and review social graphic masters: square, portrait, vertical and landscape, plus channel crops, captions and alt text. Working master sizes: 1080×1080, 1080×1350, 1080×1920 and 1920×1080. These are production defaults, not guarantees of every platform's current upload limits.
4. Produce and review a 30–60 second teaser, caption track and poster frame. Suggested 45-second cut: 0–5s useful outcome; 5–15s audience problem; 15–30s genuine working prototype; 30–38s next milestone; 38–45s CTA, destination and logo. Do not present planned integrations as working features. A pre-order requires actual price, delivery terms and payment review.
5. Save the package references, then explicitly approve the saved revision. Saving any changes clears approval. The server rejects execution without approval. Pre-launch controls remain a separate release requirement.

The current gate persists operator-supplied references and review confirmation. It does not upload, inspect, hash or render the referenced assets, measure video duration, validate destination reachability, collect waitlist entries, accept payment, publish or start workers. Declared duration is constrained to 30–60 integer seconds. Final assets have not been produced or approved for the Aegntic launch in this run.

## Workflow integration

Intent → aesthetic examples → chosen direction → launch-kit production → saved human approval → implementation → evidence → pre-launch review → authorized release → learn.

Pi Durable must check the approved creative revision immediately before execution when connected. Convex will hold the shared projection; the present local SQLite record is the first-run persistence layer. Later asset storage should pin content hashes and invalidate approval on content changes. Current edits invalidate by saved record revision; externally changed files behind the same reference are not detected.

## Recovery

No destructive migration: an additive creative table leaves existing briefs/reviews intact. Existing briefs start unapproved. Version conflicts return 409; reopening fetches the current project. Approval binds to the revision actually rendered, independently of other project updates. Database backup remains the rollback boundary. No remote deployment or publication occurred.
